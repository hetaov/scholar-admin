# 第二步:思维收敛 —— 聚焦核心与有价值的功能

> 目的:从 70 个因素中**收敛**出「用户能感知价值 + 项目能低成本实现」的功能集合。
> 方法:**价值 × 可行性二维评估**,量化打分,再按优先级(轴线)排定 P0 / P1 / P2。

---

## 2.1 收敛原则(评估标准)

对每个候选功能从两个维度打分(1-5 分):

| 维度 | 说明 |
|------|------|
| **用户价值 (V)** | 对"坚持学、学得会、记得牢"的贡献;直接影响核心体验 |
| **可行性 (F)** | 现有数据/代码支持程度;实现成本;技术风险 |

> 决策规则:**V 高且 F 高 → 立刻做;V 高 F 低 → 找简化方案或延后;V 低 → 砍掉或后置。**

|------|:------:|:--------:|:----:|---------|------|

## 2.3 收敛结论:P0 / P1 / P2

### P0 —— 立即实现(数据齐全、成本低,构成基线)

**1. 学习时间统计**(用户提出 ✅)
- 内容:用户级别累计学习时长、单次时长、日均时长
- 数据:`learning_mastery_tracking.time_spent`
- 状态:**接口已实现**(`POST /tracking/stats` → `summary.total_time_spent`)

**2. 学习进度**(用户提出 ✅)
- 内容:textbook → unit → sentence 三级进度,已学/总数/百分比
- 数据:`sentence` 集合 + 记录中的 `status/score/mastery`
- 状态:**接口已实现**(`POST /tracking/stats`)

**3. 学习次数**(用户提出 ✅)
- 内容:每个句子的学习次数、单元/教材累计学习次数、重复曝光次数
- 数据:现有记录 `sentence_id` 去重计数;建议扩展字段 `study_count`
- 状态:**待实现**(低成本,建议本轮补上)

### P1 —— 差异化核心(建议下一迭代)

**4. 滚动学习调度器** ⭐
- 内容:按遗忘曲线(间隔重复),把「已学但易忘」的句子按间隔重新推给用户
- 原理:掌握度越低、间隔越久 → 优先级越高
- 数据:`status/score/mastery` + 记录 `updated_at` 时间戳
- 产出:接口 `POST /tracking/review-plan`,返回"今日复习队列"
- 这是**把静态统计变成动态学习闭环**的关键,也是区别于普通统计工具的核心价值

**5. 薄弱点推荐**
- 内容:聚合低分(<60)句子、未学句子,生成"补漏清单"
- 与滚动学习的区别:滚动看时间,薄弱点看分数,可合并为同一调度器的输入

**6. 连续打卡/日历热力图**
- 内容:按天聚合学习行为,展示连续天数与热度,激励每日坚持

### P2 —— 后续扩展(需要更多资源或前端配合)

- 每日学习目标、游戏化徽章/排行榜、错题本、AI 对话陪练

### 暂缓(不立项)

- 语音评测/跟读(依赖 ASR 成本)、自适应难度路径(需要学习策略建模)

## 2.4 收敛逻辑说明(为什么留下这些)

1. **数据闭环优先**:P0 三项全部依赖现有数据,零埋点成本,2-3 天可交付。
2. **从"记录"到"引导"**:P1 的滚动学习把数据反哺到学习过程,形成「学习 → 记录 → 统计 → 调度 → 再学习」的正向循环,这是学习类产品最有价值的跃迁。
3. **砍掉噪音**:语音评测、自适应路径价值不低,但成本高、依赖重,现阶段做会让主干功能延期,先砍。
4. **与用户已有想法对齐**:用户提出的 4 个方向(滚动学习、学习进度、学习次数、学习时间)全部保留,其中滚动学习是 4 个里唯一的"动态功能",给予最高定位。
